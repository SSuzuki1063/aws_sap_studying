## Design Decisions

### DD-001: Composition over Replacement

Component Objects are composed into Page Objects as readonly properties. Page Objects retain all existing methods for backward compatibility. Test authors can use either:
- `indexPage.searchFor('ec2')` — existing Page Object method (unchanged)
- `indexPage.search.fill('ec2')` — Component Object method (new, finer-grained)

This dual-access pattern avoids breaking changes while encouraging migration to components for new tests.

### DD-002: Component Object Scope

Only UI components shared across 2+ pages are extracted:

| Component | Pages | Justification |
|-----------|-------|---------------|
| NavbarComponent | index, concept-map, learning-resources | Identical header/nav on all pages |
| SearchComponent | index, learning-resources | Same search UI pattern, same selectors |
| ThemeToggleComponent | index, concept-map, learning-resources | Same toggle button, same data-theme mechanism |
| ScrollToTopComponent | index, concept-map, learning-resources | Same button, same scroll behavior |

Page-specific components (concept map tree, resource list, hero section) remain in their respective Page Objects.

### DD-003: Component Object Interface

Each Component Object follows a consistent pattern:

```typescript
export class NavbarComponent {
  readonly page: Page;
  // Locators as readonly properties
  readonly header: Locator;
  readonly hamburgerBtn: Locator;

  constructor(page: Page) { ... }

  // Interaction methods
  async navigateTo(pageName: string): Promise<void> { ... }
  async isOpen(): Promise<boolean> { ... }
}
```

Components accept a Playwright `Page` instance and expose:
- Readonly locators for assertions in tests
- Interaction methods that encapsulate multi-step operations
- Query methods that return component state

### DD-004: Regression Test Organization

Each test suite follows the same structure:

```typescript
import { test, expect } from '@playwright/test';
import { IndexPage, ConceptMapPage, LearningResourcesPage } from '../helpers';

test.describe('Suite Name', () => {
  // Page Object instantiation in beforeEach
  // Tests use Page Object + Component Object methods exclusively
  // Zero CSS selectors in spec files
});
```

Tests are organized by *behavior category* (visual, navigation, links, interaction), not by page. Each spec tests the same behavior across all 3 pages where applicable.

### DD-005: Visual Regression Baseline Strategy

- First run (`--update-snapshots`) generates baseline images
- CI runs comparison against baselines with 0.5% pixel tolerance
- Baselines stored in `tests/e2e/__snapshots__/` (git-tracked)
- Separate baselines per browser-OS combination (e.g., `index-desktop-chromium-linux.png`)
- Animations disabled during capture to prevent flaky diffs
