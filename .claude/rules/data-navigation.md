# Data-Driven Navigation Rules

## Data Pipeline Overview

```
src/data/resource-registry.json   ─┐
src/data/update-history.json      ─┤
src/data/category-meta.json       ─┤
src/data/section-icons.json       ─┤  node scripts/generate-data.mjs
src/data/exam-domains.json        ─┤  ──────────────────────────────→
src/data/resource-summaries.json  ─┤
src/data/category-descriptions.json─┤
src/data/learning-modes.json      ─┤
src/data/service-registry.json    ─┘
                                       ├─ public/data.js    (runtime: categories, stats, history)
                                       ├─ public/index.js   (runtime: search index)
                                       └─ src/data/resources.ts (build-time: typed TS module)
```

`generate-data.mjs` auto-assigns new resources to categories/sections via keyword matching from `category-meta.json`. It parses two frontmatter formats: YAML and JS object literal. Warnings are emitted for unknown displayCategories and orphaned registry entries.

## Registry-Driven Data (Critical Rule 2)

Resource data is managed via `src/data/resource-registry.json` (single source of truth). **Do NOT manually edit `public/data.js`, `public/index.js`, or `src/data/resources.ts`** — they are auto-generated by `scripts/generate-data.mjs`.

### Adding/Updating Resources

1. Update `src/data/resource-registry.json` (add/modify entry)
2. Update `src/data/update-history.json` (add changelog entry at top)
3. Run `node scripts/generate-data.mjs` → generates `public/data.js`, `public/index.js`, `src/data/resources.ts`

Or use `/skill resource` / `/ship` which handle all of this automatically.

### Resource Registry Schema

Each entry in `resource-registry.json` is keyed by `directory/filename.html`:

```json
{
  "networking/aws-direct-connect-guide.html": {
    "displayCategory": "networking",
    "section": "Direct Connect & ハイブリッドネットワーク",
    "priority": "high",
    "exam_domains": [1, 2],
    "difficulty": "intermediate",
    "estimated_minutes": 20,
    "tags": ["comparison"]
  }
}
```

| Field | Required | Values |
|-------|----------|--------|
| `displayCategory` | Yes | One of 8 categories (see integration-workflow.md) |
| `section` | Yes | Section name within the category |
| `priority` | No | `"high"` / `"medium"` (default) / `"low"` |
| `exam_domains` | No | Array of domain numbers `[1-4]` |
| `difficulty` | No | `"beginner"` / `"intermediate"` / `"advanced"` |
| `estimated_minutes` | No | Reading time estimate |
| `tags` | No | Array of tags (e.g., `["comparison", "deep-dive"]`) |

### Dual Frontmatter Parsing

`generate-data.mjs` parses two frontmatter formats from `.astro` files:

1. **YAML frontmatter** (standard):
   ```
   ---
   title: 'Resource Name'
   description: 'Description'
   ---
   ```

2. **JS object literal** (legacy):
   ```javascript
   const frontmatter = { title: 'Resource Name', description: 'Description' };
   ```

The script also detects **orphaned entries** (registry entries with no matching `.astro` file) and emits warnings.

## data.js — Pure Data Only

- **NO HTML tags** in data objects — pure data only
- All HTML generation happens in `render.js` template functions
- Keep data and presentation logic completely separated

**Resource shape** (generated into `categoriesData[].sections[].resources[]`):
```javascript
{ title: 'Resource Name', href: 'category/filename.html', priority: 'high' }
```

**searchData shape** (generated into `public/index.js`):
```javascript
{ title: 'Resource Name', category: 'カテゴリ名', file: 'category/filename.html' }
```

## render.js — Single Template Pattern

ALL runtime HTML generation in centralized template functions:
- Functions: `renderCategoryQuickNav`, `renderResourceList`, `renderSection`, `renderMajorCategory`, `renderAllCategories`
- Used by `index.astro` only (learning-resources uses build-time rendering via `src/data/resources.ts`)
- `knowledge-base.astro` and `bookmark.astro` also use runtime data from `data.js`
