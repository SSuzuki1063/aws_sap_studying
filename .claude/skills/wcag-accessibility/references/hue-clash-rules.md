# 色相衝突（Hue Clash）による認知阻害の防止

## ルール ID

**WCAG-COLOR-STRUCT-002**

---

## 背景（追加理由）

高彩度・異なる色相の背景色が大きな面積で隣接すると、利用者に **認知的な違和感・疲労・意味誤認** を生じさせる可能性がある。

これは WCAG 2.1 の以下の達成基準の趣旨に反する恐れがある：

| 達成基準 | 概要 |
|---------|------|
| **1.4.1 色の使用** | 色だけに意味を依存しない |
| **1.3.1 情報及び関係性** | 視覚的手がかりに依存しない構造理解 |

---

## 判定原則

> **NG-006-A〜E のいずれかに該当した時点で NG と判定する。**
> **「軽微」「許容範囲」といった裁量判断は行わない。**

このルールは「考えさせない」ための即断アンカーとして機能する。
迷った場合は NG として扱う。

---

## NG-006 サブカテゴリ（即断ルール）

### NG-006-A: 高彩度 × 異色相 × 大面積が連続している

#### 例

- 赤背景のヒーロー直下に、青背景のセクション
- 紫背景の説明ブロック直下に、緑背景のまとめブロック

#### NG理由

- 色相の切り替えが「意味の切り替え」より先に知覚される
- 認知が分断され、文脈の連続性が失われる

#### 即断条件

> **「背景色が変わった理由を一文で説明できない」場合 → NG**

---

### NG-006-B: 警告・危険文脈の色（赤系）を装飾用途で使用

#### 例

- 技術解説ページのヒーロー全面が赤
- 「自動化」「工場」など比喩表現のために赤背景を使用

#### NG理由

- 赤はユーザーに「異常・緊急」を想起させる
- 内容と感情誘導が一致しない

#### 即断条件

> **エラーメッセージでないのに赤が面積的に使われている → NG**

---

### NG-006-C: 色相切り替えが構造情報なしに行われている

#### 例

- 背景色だけが変わり、見出し・ラベル・説明が変わらない
- 同じ説明文レベルなのに色だけが変わる

#### NG理由

- 色だけに意味を担わせている状態
- WCAG 1.4.1（色の使用）の精神違反

#### 即断条件

> **モノクロ表示にしたら意味の違いが消える → NG**

---

### NG-006-D: 同一ページ内で複数の「主張色」が競合している

#### 例

- セクションA：オレンジが主役
- セクションB：グリーンが主役
- セクションC：パープルが主役

#### NG理由

- ユーザーの注意が常にリセットされる
- 何が重要か判断できない

#### 即断条件

> **「このページの基調色は何か？」に即答できない → NG**

---

### NG-006-E: 異色相の切り替えが「情報の格」を誤認させる

#### 例

- 同列の説明ブロックなのに、1つだけ色相が異なる
- 補足情報が派手な色、主要情報が地味な色

#### NG理由

- 視覚的主従と意味的主従が逆転
- 情報理解を誤らせる

#### 即断条件

> **「なぜこのブロックだけ色が違うのか説明できない」→ NG**

---

## 補助ルール（レビュー時の最終判断）

レビューで迷った場合は、以下の質問を必ず投げる：

> **Q：この色の違いは、ユーザーに「何が違う」と伝えたいのか？**
> → 言語化できなければ **NG-006 該当**

---

## 判定ルール（Yes / No チェックリスト）

### Q1. 高彩度背景の隣接

**高彩度（鮮やかな）背景色が、広い面積で隣接していないか？**

例：赤 × 青、赤 × 緑、紫 × 黄 など

- ☐ **Yes**（隣接していない）→ PASS
- ☐ **No**（隣接している）→ **NG**

### Q2. 色相切り替えと意味の一致

**背景色の色相切り替えは、意味的な区切り（文脈・役割・章構造）と一致しているか？**

- ☐ **Yes**（一致している）→ PASS
- ☐ **No**（装飾的な切り替え）→ **NG**

### Q3. 構造情報の併記

**色の切り替えが、見出し・ラベル・説明文などの構造情報なしに行われていないか？**

- ☐ **Yes**（構造情報が併記されている）→ PASS
- ☐ **No**（色だけで区切りを表現）→ **NG**

### Q4. 警告色の誤用

**警告・危険・エラー文脈で用いられる色相（赤系）が、装飾目的やヒーロー背景として使用されていないか？**

- ☐ **Yes**（使用していない）→ PASS
- ☐ **No**（装飾目的で赤系を使用）→ **NG**

### Q5. 文脈の混在

**色相衝突によって、「緊急」「警告」「通常」「説明」といった文脈が混在して見えないか？**

- ☐ **Yes**（混在していない）→ PASS
- ☐ **No**（文脈が混乱する）→ **NG**

## 数値・定性的補足（判定の指針）

### 原則

| 原則 | 説明 |
|------|------|
| 高彩度 × 大面積 × 隣接は原則 NG | 視覚的疲労と意味混乱の原因 |
| 同一ページ内の主背景色は原則 1 系統 | 認知的一貫性を確保 |

### 異なる色相を使う場合の必須条件

以下の**いずれか**を必ず満たすこと：

1. **明確な意味ラベル** - 「注意」「情報」等のテキストラベル
2. **セクション見出し** - h2/h3等の見出しで文脈を明示
3. **十分な余白・緩衝帯** - 白/グレーのスペースで視覚的に分離

## NG パターン

### パターン1: 高彩度背景の連続

```
┌─────────────────────────┐
│ 高彩度 赤背景           │  ← ヒーローセクション
│ #DC143C                 │
├─────────────────────────┤
│ 高彩度 青背景           │  ← 直下のセクション
│ #1E90FF                 │
└─────────────────────────┘
```

**問題点：**
- 赤×青の強い色相衝突
- 色の切り替えが「装飾的」で意味説明がない
- AWS/技術解説文脈にもかかわらず、警告色が面全体に使用されている

### パターン2: 警告色の装飾利用

```html
<!-- NG: 赤系をヒーロー背景に使用 -->
<section class="hero" style="background: #b91c1c;">
    <h1>AWS Lambda完全ガイド</h1>
</section>
```

**問題点：**
- 赤は「警告」「エラー」「危険」の意味を持つ
- 技術解説コンテンツのヒーローに使うと意味が混乱

## OK パターン

### パターン A: 同系色での明度差

```
┌─────────────────────────┐
│ ネイビー（ヒーロー）    │
│ #232F3E                 │
├─────────────────────────┤
│ ダークブルー（説明）    │
│ #374151                 │
└─────────────────────────┘
```

**良い点：**
- 色相は同一（青系統）
- 明度差で視覚的区切りを表現
- 意味の連続性が保たれる

### パターン B: アクセントとしての異色相

```css
/* 背景：中立色（白・グレー・ネイビー） */
.section {
    background: #ffffff;
}

/* 強調：アイコン/下線のみ異色相 */
.section .accent-icon {
    color: #dc7600;  /* AWS Orange */
}

.section .highlight {
    border-bottom: 2px solid #dc7600;
}
```

**良い点：**
- 背景は中立色で統一
- 異色相は小面積のアクセントのみ
- 色相衝突による認知負荷がない

### パターン C: 構造情報による分離

```html
<!-- OK: 見出しと余白で意味を明示 -->
<section class="info-section" style="background: #eff6ff;">
    <h2>基本概念</h2>
    <p>説明内容...</p>
</section>

<div class="separator" style="height: 24px; background: #f9fafb;"></div>

<section class="warning-section" style="background: #fef2f2;">
    <h2>注意事項</h2>
    <p>警告内容...</p>
</section>
```

**良い点：**
- 各セクションに見出しで文脈を明示
- 緩衝帯（separator）で視覚的に分離
- 色だけでなく構造情報で意味を伝達

## 推奨カラースキーム

### AWS学習リソース向け

| 役割 | 背景色 | 備考 |
|------|--------|------|
| メインコンテンツ | `#ffffff` | 中立・情報提示 |
| サブセクション | `#f9fafb` | 微細な区切り |
| ヘッダー/フッター | `#232F3E` | AWS Dark（権威・ナビ） |
| 情報ボックス | `#eff6ff` | 薄い青（補足情報） |
| 警告ボックス | `#fef2f2` | 薄い赤（小面積のみ） |
| 成功ボックス | `#f0fdf4` | 薄い緑（小面積のみ） |

### 避けるべき組み合わせ

| 組み合わせ | 理由 |
|-----------|------|
| 赤背景 → 青背景 | 最も強い色相衝突 |
| 紫背景 → 黄背景 | 補色関係で視覚疲労 |
| 緑背景 → 赤背景 | 信号色の混乱 |
| 高彩度オレンジ → 高彩度青 | 温冷のコントラストが強すぎる |

## 検出方法

### 手動レビュー項目

1. ページ全体をスクロールして、隣接セクションの背景色を確認
2. 色の切り替え箇所に見出し/ラベルがあるか確認
3. 赤系の色が警告以外の文脈で使われていないか確認

### 自動検出（将来的な実装候補）

```python
# 色相衝突検出の基本ロジック
def detect_hue_clash(section_colors):
    """隣接セクションの色相差を検出"""
    for i in range(len(section_colors) - 1):
        hue1 = get_hue(section_colors[i])
        hue2 = get_hue(section_colors[i + 1])
        saturation1 = get_saturation(section_colors[i])
        saturation2 = get_saturation(section_colors[i + 1])

        # 高彩度（>50%）かつ色相差が大きい（>60°）場合にフラグ
        if saturation1 > 0.5 and saturation2 > 0.5:
            if abs(hue1 - hue2) > 60:
                yield f"色相衝突の可能性: {section_colors[i]} ⟷ {section_colors[i + 1]}"
```
