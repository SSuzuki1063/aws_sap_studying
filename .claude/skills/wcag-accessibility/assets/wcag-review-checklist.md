# WCAG 2.1 AA レビューチェックリスト

Yes/No形式のレビューチェックリストです。新規ページ作成時やデプロイ前の最終確認に使用してください。

---

## 使い方

1. 各項目に Yes / No / N/A で回答
2. すべて Yes または N/A になるまで修正
3. No がある場合は対応策を実施してから再確認

## 4. キーボード・フォーカス

| # | チェック項目 | Yes/No/N/A | 備考 |
|---|-------------|-----------|------|
| 4.1 | すべてのインタラクティブ要素にTabキーでフォーカスできるか？ | | |
| 4.2 | フォーカス順序は論理的で意味のある順序か？ | | |
| 4.3 | フォーカスインジケーターは視覚的に明確か？ | | |
| 4.4 | キーボードトラップ（フォーカスが抜け出せない状態）がないか？ | | |

### 手動テスト方法

1. ページを開く
2. マウスを使わずにTabキーのみで移動
3. すべてのリンク・ボタン・フォーム要素にフォーカスできることを確認
4. Enter/Spaceキーで要素を操作できることを確認
5. モーダルはEscキーで閉じられることを確認

### よくある問題

- `<div onclick>` を使用 → `<button>` に変更、または `role="button"` と `tabindex="0"` を追加
- `outline: none` でフォーカス表示を削除 → 代替のフォーカススタイルを提供

## 7. 同系色背景×同系色文字の禁止（NG-007）

> **判定原則：同系色の背景と本文文字の組み合わせは原則禁止。本文は常に無彩色（ニュートラル）を使用。**

| # | チェック項目 | Yes/No/N/A | 備考 |
|---|-------------|-----------|------|
| 7.1 | 本文テキスト（段落・箇条書き）の文字色は、背景色と同系色になっていないか？ | | |
| 7.2 | 同系色を使用する場合（ブランド表現等）、装飾（枠線・アイコン・見出し下線）に限定しているか？ | | |
| 7.3 | 本文テキストのコントラスト比は、実効背景色に対して 4.5:1 以上を満たすか？ | | |
| 7.4 | 見出し（大きな文字）で同系色を使う場合でも、コントラスト比 3.0:1 以上を満たしているか？ | | |

### NGパターン例

| NG | OK |
|----|-----|
| 薄緑背景に緑文字 | 薄緑背景に`#1f2937`（ニュートラル） |
| 薄紫背景に紫文字 | 紫はアイコン・見出し下線のみ |
| 薄ベージュ背景にオレンジ本文 | オレンジは枠線・アクセントのみ |

### 推奨設計

1. **本文テキストは原則ニュートラル（無彩色）固定** → `#374151`, `#1f2937`
2. **セクションのテーマカラーは「背景・枠・アイコン」に使う**
3. **「同系色文字を使いたい誘惑」を設計で遮断する（トークン化）**

### 詳細ドキュメント

`references/ng-patterns.md` の NG-007 を参照

## 8. 色相衝突（Hue Clash）

> **判定原則：NG-006-A〜E のいずれかに該当した時点で NG。裁量判断は行わない。**

| ID | チェック項目 | 即断条件 | 結果 |
|----|-------------|---------|------|
| NG-006-A | 高彩度×異色相×大面積が連続していないか？ | 「背景色が変わった理由を一文で説明できない」→ NG | |
| NG-006-B | 警告色（赤系）を装飾用途で使用していないか？ | 「エラーでないのに赤が面積的に使われている」→ NG | |
| NG-006-C | 色相切り替えに構造情報が併記されているか？ | 「モノクロ表示で意味の違いが消える」→ NG | |
| NG-006-D | 同一ページ内で複数の主張色が競合していないか？ | 「基調色は何か？」に即答できない → NG | |
| NG-006-E | 異色相の切り替えが情報の格を誤認させないか？ | 「なぜこのブロックだけ色が違うか説明できない」→ NG | |

### 補助ルール（最終判断）

迷った場合は以下の質問を投げる：

> **Q：この色の違いは、ユーザーに「何が違う」と伝えたいのか？**
> → 言語化できなければ **NG-006 該当**

### 関連WCAG基準

- **1.4.1 色の使用** - 色だけに意味を依存しない
- **1.3.1 情報及び関係性** - 視覚的手がかりに依存しない構造理解

### 詳細ドキュメント

`references/hue-clash-rules.md` を参照

## 9. 同列情報の非対称レイアウト（NG-008）

> **判定原則：意味的に同列な要素は視覚的にも同列に配置する。非対称を使う場合は意味的理由を明示。**

| # | チェック項目 | Yes/No/N/A | 備考 |
|---|-------------|-----------|------|
| 9.1 | 同一セクション内で意味的に同列な情報要素は、視覚的にも同列（同サイズ・同カラム構造）で配置されているか？ | | |
| 9.2 | 3:1、3+1 などの非対称グリッドを使用している場合、その非対称性に明確な意味的理由（主従・補足・概念/具体の差）が明示されているか？ | | |
| 9.3 | 非対称レイアウトによって、「一部の情報が補足・重要度が低い」と誤認される可能性はないか？ | | |
| 9.4 | 視覚的な配置に依存せず、見出し・ラベル・説明文のみで情報の関係性が理解可能か？ | | |

### NGパターン例

| NG | OK |
|----|-----|
| 4要素を3+1に分割（下段が「余り」に見える） | 2×2グリッドで均等配置 |
| 下段要素に「補足」等の意味ラベルなし | 「共通原理」「基盤」等で非対称の理由を明示 |
| 同列カードのサイズ不揃い | 全カード同一サイズ |

### 推奨設計

1. **同列要素は原則として均等グリッド（2×2, 3×2 等）**
2. **非対称を使う場合は必ず：**
   - 見出し・ラベルで意味差を明示
   - サイズ・背景・余白で「意図的」と分かる差を付ける
3. **モノクロ/スクリーンリーダーでも関係性が理解可能**

### 関連WCAG基準

- **1.3.1 情報及び関係性** - 視覚表現に依存しない構造理解
- **2.4.6 見出し及びラベル** - 主題・目的を説明する見出し・ラベル

### 詳細ドキュメント

`references/ng-patterns.md` の NG-008 を参照
