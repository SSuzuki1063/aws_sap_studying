🤔 AWS Elastic Disaster Recovery って何？

📝 簡単に言うと...

会社のサーバーや大事なデータ を、 AWS に 常時バックアップ しておき、 災害が起きた時に すぐに代替システムを起動 できるサービスです

本社ビル で火災や地震が発生！

すぐに業務を再開したい


👆 普段から準備が必要...
🏭 緊急避難所 を用意しよう！

🏗️ AWS EDRの4つの重要な要素

👨‍💼

レプリケーションエージェント
= 専属コピー係

源データの監視役 です。
書類整理係のように、 本社の重要書類 （データ）を
常時チェック して変更があるたびに
避難所に 最新版をコピー します。

特徴: 24時間365日監視
頻度: リアルタイム同期
🏭

ステージングエリア
= 避難所の準備倉庫

緊急時の準備場所 です。
避難所の倉庫のように、
本社からコピーした書類やデータを
すぐに使える状態 で保管します。

役割: データの一時保管
状態: 即座に起動可能
🏢

リカバリインスタンス
= 緊急時の代替オフィス

実際の業務継続場所 です。
避難所の仮設オフィスのように、
災害時に 実際の業務 を行う
代替システム が動く場所です。

機能: 本格的な業務継続
性能: 本社と同等
📋

コンソール
= 災害対策本部

災害対応の司令塔 です。
災害対策本部のように、
復旧作業の進捗 を監視し、
ワンクリック で復旧を開始します。

操作: 簡単な画面操作
監視: リアルタイム状況確認

⏱️ RTO・RPOって何？復旧目標を理解しよう

🎯 災害復旧の2つの重要な目標

⏰

RTO (Recovery Time Objective)

= 復旧時間目標


🏢 災害対策の例:
「火災から何時間で
代替オフィスで業務再開？」


💻 AWS EDRの場合:
「システム障害から
何分で復旧完了？」


AWS EDRの目標:
⚡ 数分〜数時間
📊

RPO (Recovery Point Objective)

= 復旧ポイント目標


🏢 災害対策の例:
「最大何時間前のデータまで
失ってもOK？」


💻 AWS EDRの場合:
「最大何分前のデータまで
失ってもOK？」


AWS EDRの目標:
📈 数秒〜数分

💡 具体的な例で理解しよう

📋 シナリオ: 朝10:00にサーバー障害発生


⏰ RTO = 2時間の場合:

  • 12:00（正午）までに復旧完了が目標
  • AWS EDRで実際は10:15には復旧（大幅にクリア！）

📊 RPO = 15分の場合:

  • 9:45以降のデータは復旧できればOK
  • AWS EDRなら9:59のデータまで復旧可能（余裕でクリア！）

💰 コスト比較 - 従来の災害対策 vs AWS EDR

💸 どのくらいお得？

🏢

従来のDR

物理的な代替サイト


💰 初期費用:

  • データセンター構築: 数千万円〜
  • 機器購入: 数百万円〜
  • ネットワーク構築: 数百万円

🔄 運用費用:

  • 月額賃料: 50万円〜
  • 保守費用: 20万円〜/月
  • 人件費: 30万円〜/月
総額: 年間数千万円
☁️

AWS EDR

クラウド型DR


💰 初期費用:

  • セットアップ: 0円
  • 機器購入: 0円
  • 設定作業: 数日

🔄 運用費用:

  • ステージング: 3〜10万円/月
  • データ転送: 1〜5万円/月
  • 復旧時のみ: 本格料金
総額: 年間50〜200万円
❌

災害対策なし

何も備えない場合


💰 平常時費用:

  • DR関連: 0円
  • 備え: なし

⚠️ 災害時リスク:

  • 業務停止: 数日〜数週間
  • 売上損失: 数千万円〜
  • 信用失墜: プライスレス
  • 復旧作業: 数百万円〜
リスク: 計り知れない損失

🎯 AWS EDRの圧倒的メリット

💰 コスト面

  • 初期費用: ほぼ0円
  • 運用費用: 従来の1/10以下
  • 使った分だけ課金

⚡ 技術面

  • 設定: 数時間〜数日
  • 復旧: 数分〜数時間
  • 管理: GUI操作のみ

📋 実際の設定手順（超簡単版）

1

避難計画の策定

AWS EDRの初期設定
→ 災害対策本部（AWSコンソール）にアクセス
→ 「何を」「どこに」「どのくらいの頻度で」バックアップするかを決定
→ レプリケーション設定テンプレートを作成

2

コピー係を本社に配置

レプリケーションエージェントをインストール
→ 保護したいサーバーに「コピー係」ソフトウェアをインストール
→ エージェントがAWSとの通信チャネルを確立
→ 初回の完全バックアップを開始（数時間〜1日）

3

避難所の準備

ステージングエリアの自動構築
→ AWS上に「準備倉庫」が自動的に作成される
→ 低コストなインスタンスで常時データを同期
→ 変更差分のみを継続的にレプリケーション

4

避難訓練の実施

復旧テストの実行
→ 「テスト復旧」機能で実際の復旧手順を確認
→ 本番環境に影響なしで復旧時間を測定
→ 問題があれば設定を調整

5

緊急時の対応準備

フェイルオーバー計画の準備
→ 災害発生時の担当者と連絡手順を決定
→ ワンクリック復旧の手順書を作成
→ 社内への通知方法を準備

6

災害対策完了！

24時間365日の保護開始
→ コピー係が常時監視・バックアップを実行
→ 災害発生時はワンクリックで復旧開始
→ 安心して本業に集中できる環境が完成

❓ よくある質問

🤔 どんなシステムが対象になるの？

ほぼ全てのシステム が対象です！


対応OS:

  • Windows Server（2008以降）
  • Linux（RHEL、Ubuntu、CentOS等）

対応環境:

  • 物理サーバー
  • VMware vSphere環境
  • 他のクラウド環境（Azure、GCP）
⚡ 復旧にはどのくらい時間がかかるの？

システムの規模によりますが、 驚くほど高速 です！


⏰ 復旧時間の目安:

  • 起動指示 : 数クリック（1分以内）
  • 小規模システム : 5〜15分
  • 中規模システム : 15〜60分
  • 大規模システム : 1〜4時間

従来の災害対策（数日〜数週間）と比べると 圧倒的に高速 です！

💰 料金体系はどうなってるの？

使った分だけ の明確な料金体系です！


💰 主な料金要素:

  • ステージング費用 : 1台あたり月額$5〜30（保護対象のサーバー数による）
  • データ転送費用 : $0.09/GB（初回のみ、差分は微小）
  • 復旧時のEC2費用 : 使用期間のみ（通常のEC2料金）

💡 コツ: 普段は最小コスト、災害時のみ本格運用で経済的！

🔧 設定は本当に簡単？

めちゃくちゃ簡単 です！ ITに詳しくない人でも大丈夫！


🎯 簡単な理由:

  • ウィザード形式 : 画面の指示に従うだけ
  • 自動検出 : サーバーの情報を自動で認識
  • テンプレート : よくある設定パターンを用意済み
  • 日本語サポート : 困った時は日本語で相談OK

⏱️ 設定時間: 1台あたり30分〜2時間程度

🌍 どこのリージョンを選べばいい？

日本にある会社なら東京リージョン がおすすめです！


🏯 東京リージョンのメリット:

  • 低遅延 : 日本からのアクセスが最速
  • 法令対応 : 日本の法律・規制に準拠
  • データ主権 : データが日本国内に保管
  • 災害分散 : 本社と異なる地域でリスク分散

🌏 別の選択肢: さらなるリスク分散が必要なら大阪リージョンも検討
